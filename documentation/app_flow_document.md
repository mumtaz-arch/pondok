# App Flow Document

## Onboarding and Sign-In/Sign-Up
When a brand-new visitor arrives at the application by typing the root URL or following a shared link, they see the Welcome Page. This page introduces the brand, highlights the core value proposition, and provides clear calls to action to register or log in. If the visitor clicks the registration link, they land on the Register Page, which prompts them to enter their name, a valid email address, and a secure password twice for confirmation. When they submit the registration form, the system creates their account, triggers an email verification message, and redirects them to a Verification Notice Page. On that page, a message explains that they need to confirm their email by clicking on the link sent to their inbox. Once they verify, or immediately if email verification is not enforced, the user is automatically signed in and guided to the main Dashboard.

If a user clicks the login link on the Welcome or Register Page, they reach the Login Page. This page asks for an email and password. It also offers a "remember me" checkbox and a link for forgotten passwords. Submitting the login form authenticates the user and directs them to the Dashboard. If authentication fails, the page displays a clear error message and retains the email field. When a user clicks the "Forgot Your Password?" link, they navigate to the Password Reset Request Page. There they enter their email address. The system then emails them a secure reset link. Clicking that link opens the Password Reset Page, where the user sets a new password and confirms it. On success, the system logs them in and returns them to the Dashboard. To sign out at any time, the user selects the logout option in the header’s profile menu, which immediately ends the session and sends them back to the Welcome Page.

## Main Dashboard or Home Page
Upon successful login or email verification, the user arrives at the Dashboard Page located at `/dashboard`. The Dashboard displays a clean header at the top showing the application name, a search input field, and a user profile dropdown menu. Along the left side, a vertical sidebar presents the main navigation links for each core module of the application. The central area showcases dynamic widgets such as recent activity, system notifications, and quick links to frequent tasks. Each sidebar link highlights on hover and on selection, and clicking any link instantly loads the appropriate module page without reloading the entire header or sidebar. The Dashboard also features a notifications bell icon in the header that shows a small badge count of unread alerts. Every element on the Dashboard is designed to give the user a high-level view of their data and a clear path to deeper features.

## Detailed Feature Flows and Page Transitions
When a user selects the "Users" link in the sidebar, they are taken to the Users Listing Page at `/users`. Here a paginated table lists all existing user accounts. From this page, clicking "Create New User" opens a form page at `/users/create` where one can input a name, email, password, and assign roles. Submitting that form returns the user to the Users Listing Page and shows a success banner. Viewing details for any user is as simple as clicking on their row in the table, which routes to `/users/{id}` and displays that user’s profile information, roles, and permissions. If the user chooses to modify any information or roles, they click "Edit" to go to `/users/{id}/edit`. On saving changes, they return to the detail view with an update confirmation message. Deleting a user triggers a confirmation prompt and, on acceptance, redirects back to the listing page with a deletion banner.

Role and permission management follows a similar pattern under the "Roles" and "Permissions" links. Each module uses resourceful routes for listing, creating, editing, viewing, and deleting entries. Access controls are enforced at every step, so only users with the proper Spatie Laravel Permission rights can see or interact with those module pages.

The "Data Import/Export" section opens at `/data-import-export`. On this page, a Livewire-powered upload component lets the user drag and drop an Excel file. As soon as the file is dropped, the component validates its structure, displays inline errors for missing columns, and shows a progress bar during the import process. If the dataset is large, a background job handles the import and notifies the user by email when complete. On the same module page, an export panel lists available data sets. Clicking an export button starts generating an Excel file via the Maatwebsite package and begins an immediate download. A modal overlay keeps the user informed of progress and success.

When the user accesses the "Notifications" link in the sidebar or the bell icon in the header, a real-time feed appears. This feed updates instantly whenever the server pushes new events through Pusher. The full Notifications Page at `/notifications` shows a chronological list of messages, each marked read or unread. Tapping on a notification expands its details and marks it as read. Users can clear individual items or all read items at once.

A global search input in the header uses Meilisearch to fetch full-text search results as the user types. A live dropdown groups suggestions by model type, and arrow keys let the user navigate results. Pressing enter or clicking "View All Results" takes the user to `/search`, where a paginated list of results appears. On that page, they can refine results using checkboxes and date-range filters.

Under "Media Library," the user sees a grid of uploaded files at `/media`. A Livewire modal for "Upload Media" accepts images and documents via drag-and-drop. The component instantly generates and displays thumbnails or file icons and updates the grid without a full page reload. Clicking any media item opens a detail page at `/media/{id}`. There, the user can view metadata, trigger Spatie Media Library conversions, rename the file, or delete it. All actions happen through Livewire calls that update the interface in real time.

When the user selects "Payments," they arrive at `/payments`. This page displays current subscription status and lists past transactions. A button labeled "Make a Payment" routes them to `/payments/checkout`, where they choose a plan or enter an amount for a one-time charge. They then enter credit card or e-wallet details through the Midtrans SDK. After submitting, the system shows a spinner while awaiting gateway confirmation. Success redirects back to the payments page with a receipt visible. In the background, webhook endpoints update transaction status, which appears live to the user.

The "Reports" section at `/reports` lets the user generate server-side PDFs. They pick a report type, set parameters like date range or user filters, and click "Generate PDF." The application uses Barryvdh Laravel Snappy to convert a Blade view into a high-quality PDF. If the report is small, it downloads immediately. For large reports, a background job runs, and the user gets a notification when it is ready for download.

Throughout these modules, navigation between pages always passes through the shared header and sidebar. Breadcrumbs at the top of each page reflect the user’s path, making it easy to go back to parent screens. Page transitions are smooth, and Livewire components update without full page reloads when possible.

## Settings and Account Management
In the header’s profile dropdown, the user clicks "Profile Settings" to reach `/settings/profile`. On that page, they can update their display name, change their email address, upload a new avatar, and update their password by entering the current and new password twice. All fields validate in real time, and saving changes shows a confirmation banner. From the same dropdown, selecting "Notification Preferences" opens `/settings/notifications`, where toggles let the user enable or disable email alerts, in-app broadcasts, and SMS notifications. Next, the "Billing and Subscription" link leads to `/settings/billing`. Here the user reviews their active plan, sees upcoming invoice dates, updates payment methods, upgrades or downgrades plans, and cancels subscriptions. Each action triggers a prompt to confirm the choice and returns the user to the billing page with a success or error message. A "Back to Dashboard" link at the top of every settings page returns them to `/dashboard`.

## Error States and Alternate Paths
If a user submits any form with invalid or missing information, the form’s Livewire component immediately highlights each erroneous field in red and displays a descriptive error message below the input. If the application loses connectivity during an AJAX request or Livewire interaction, a banner appears at the top stating "Connection lost. Reconnecting…" Once online, Livewire automatically retries the failed request. Attempting to access a page without sufficient permissions redirects the user to a custom 403 Forbidden Page that explains the restriction and offers a link back to the Dashboard. Navigating to an undefined route displays a user-friendly 404 Page Not Found screen with a search bar and a button to return to the home page. Server-side exceptions produce a custom 500 Error Page that informs the user that something went wrong and invites them to contact support. In every error scenario, the user has a clear path to recover, either by fixing form inputs, logging in again, or returning to a safe landing page.

## Conclusion and Overall App Journey
From the start, a new visitor sees a simple welcome screen that funnels them into registering or logging in. The onboarding flow covers account creation, email verification, password recovery, and logout. Once signed in, the Dashboard provides a comprehensive overview and a sidebar for navigating all core modules. Each feature area—user and role management, data import and export, media handling, real-time notifications, search, payments, PDF reports, and account settings—is organized into its own resourceful set of pages. Livewire enhances interactivity throughout, while Pusher powers live updates. Settings pages allow profile customization, notification control, and billing management before guiding the user back into the main application. Built-in error pages and inline validation keep the user informed whenever something unexpected occurs. Taken together, the pondok boilerplate delivers a connected, end-to-end user journey that starts with sign-up and extends through every advanced feature, ensuring no action or page feels isolated or incomplete.
